# คู่มือ AI — ใบแต่งทนายความ (แบบพิมพ์ศาล ๙) · v2

**เอกสารนี้เขียนให้ AI อ่าน** เมื่อถูกขอให้เปลี่ยนข้อมูลดิบของคดี (อีเมล คำฟ้อง
หมายเรียก หนังสือมอบอำนาจ) ให้เป็นไฟล์ `.poa.json` ที่
`litigation-tools/attorney-appointment.html` เปิดแล้วส่งออกเป็น `.docx` ได้ทันที

เครื่องมือ **ไม่สร้างแบบฟอร์มใหม่** มันใช้ไฟล์ Word ของสำนักงานสองไฟล์ตามที่เป็นอยู่
แล้วพิมพ์ข้อความลงใน run เดิมของแต่ละช่อง — ฟอนต์ ขีดเส้นใต้ ภาษา และถ้อยคำอื่นทั้งหมด
คงเดิม งานของ AI จึงมีอย่างเดียว คือ **หาค่าที่ถูกต้องมาใส่ให้ครบ และให้สั้นพอดีบรรทัด**

---

## ๑. สิ่งที่เครื่องมือไม่แตะ — AI ไม่ต้องและไม่ควรส่งมา

| ส่วนของแบบฟอร์ม | เหตุ |
|---|---|
| ข้อความเรื่อง **อำนาจ*** (ม.๖๒) | ใช้ตามไฟล์ต้นฉบับทุกตัวอักษร เลือกได้แค่แบบ (ข้อ ๒) |
| **ที่อยู่ปัจจุบัน / ที่อยู่สำนักงาน** ในคำรับเป็นทนายความ | เป็นที่อยู่สำนักงานตามไฟล์ PY ทั้งสองแบบ |
| “ทั่วราชอาณาจักร” · คำที่ขีดฆ่า (ตรอก/ซอย ตำบล อำเภอ) | คงเดิม |
| ช่อง “คำสั่ง” / “ผู้พิพากษา” | เว้นให้ศาล |

## ๒. เลือกแบบ — `tpl`

| ค่า | ไฟล์ต้นทาง | ถ้อยคำในวงอำนาจ | ที่สำนักงานใช้ |
|---|---|---|---|
| `"JDA"` | ใบแต่งทนายความ JDA | “**การถอนคำให้การ**” | ฝ่ายจำเลย |
| `"PY"`  | ใบแต่งทนายความ PY  | “**การถอนฟ้อง**” | ฝ่ายโจทก์ |

เลือกตามฝ่ายของลูกความเป็นค่าตั้งต้น แต่ **เป็นดุลพินิจของทนาย** — ถ้าผู้ใช้สั่งแบบใด ใช้แบบนั้น
แบบใช้กับทั้งคดี (ทุกลูกความในไฟล์เดียวกัน)

## ๓. โครงของไฟล์

ส่งกลับ **JSON หนึ่งอ็อบเจ็กต์** ไม่มีคำอธิบาย ไม่มี code fence บันทึกเป็น `<ชื่อเรื่อง>.poa.json`
ถ้าจะถามหรือเตือนอะไร ให้พูดแยกออกมานอกไฟล์

```jsonc
{
  "tool": "attorney-appointment",
  "version": 2,
  "state": {
    "tpl": "JDA",
    "cse": {
      "matter": "01 บริษัท ก.",         // ใช้ตั้งชื่อไฟล์เท่านั้น ไม่พิมพ์ลงเอกสาร
      "blackNo": "พ.123",               // อักษรนำ + เลข ไม่ต้องมี /๒๕..
      "blackYear": "69",                // สองหลักท้ายของ พ.ศ.
      "redNo": "", "redYear": "",       // ปกติยังไม่มี — เว้นว่าง
      "court": "แพ่งกรุงเทพใต้",          // เฉพาะส่วนหลังคำว่า "ศาล"
      "caseType": "แพ่ง",
      "dateIso": "",                    // "2026-10-01" หรือ "" = เว้นไว้เขียนเองตอนลงนาม
      "day": null, "month": null, "year": null,   // null = คำนวณจาก dateIso
      "partyA": "บริษัท ก. จำกัด", "roleA": "โจทก์",
      "partyB": "นาย ข. กับพวกรวม 3 คน", "roleB": "จำเลย"
    },
    "clients": [
      {
        "name": "นาย ข.",               // ช่อง "ขอรับเป็นทนายความของ"
        "role": "จำเลยที่ 1",           // ฐานะของลูกความ (ท้ายบรรทัดเดียวกัน)
        "appointer": "นาย ค.",           // ช่อง "ข้าพเจ้า" (ผู้แต่งทนายความ)
        "appointerRole": null,          // null = auto (ดูข้อ ๔.๒)
        "appointerSig": null,           // null = auto — ชื่อในวงเล็บใต้ลายมือชื่อผู้แต่ง
        "lawyers": ["KT"]               // ชื่อย่อทนายในทะเบียน — ได้คนละฉบับ
      }
    ],
    "firm": { "officePhone": null },
    "opts": { "thaiDigits": true, "maxCondense": 15 }
  },
  "lawyers": [
    { "key": "KT", "name": "นาย ก. ตัวอย่าง", "idNo": "", "licenseNo": "1234/2567", "phone": "", "email": "" }
  ]
}
```

ตัวอย่างทั้งหมดในคู่มือนี้เป็นชื่อสมมติ

## ๔. กติกาการกรอก

### ๔.๑ หัวคดี

| ช่อง | กติกา |
|---|---|
| `blackNo` | อักษรนำตามที่ศาลออก (`พ.`, `พE`, `ผบ.` …) + เลข พิมพ์เลขอารบิกได้ ระบบแปลงเป็นเลขไทย |
| `blackYear`, `redYear`, `year` | **สองหลักท้าย** ของ พ.ศ. (`69`) — ใส่สี่หลักมา ระบบตัดเหลือสองหลัก |
| `redNo` | ตอนยื่นใบแต่งมักยังไม่มี → เว้นว่าง ห้ามเดา |
| `court` | ห้ามใส่คำว่า “ศาล” ซ้ำ (ถ้าใส่มา ระบบตัดให้) |
| `dateIso` | วันที่ลงนามในใบแต่ง ไม่ใช่วันฟ้อง — ไม่รู้ให้ `""` แบบฟอร์มจะเว้นเส้นไว้ให้เขียน |

### ๔.๒ ช่อง “ข้าพเจ้า … ผู้แต่งทนายความ”

* **ผู้รับมอบอำนาจลงนาม** (พบบ่อยที่สุด): `appointer` = ชื่อผู้รับมอบอำนาจ, `appointerRole: null`
  → ระบบเขียน “ผู้รับมอบอำนาจ” + ฐานะลูกความ เช่น “ผู้รับมอบอำนาจจำเลยที่ ๑”
* **ลูกความลงนามเอง**: `appointer` = ชื่อเดียวกับ `name` → ระบบเขียนแค่ฐานะ เช่น “จำเลยที่ ๑”
* **นิติบุคคลโดยผู้รับมอบอำนาจ**: `appointer` = `"บริษัท ก. จำกัด โดยนาย ค. ผู้รับมอบอำนาจ"`,
  `appointerRole: ""` → ชื่อใต้ลายมือชื่อ auto เป็น “นาย ค. ผู้รับมอบอำนาจ”

**อย่าเดาว่าใครเป็นผู้รับมอบอำนาจ** ถ้าเอกสารดิบไม่บอก ให้เว้นว่างแล้วบอกผู้ใช้แยกต่างหาก

### ๔.๓ ความยาว — เอกสารต้องจบในสองหน้า

ทุกช่องเป็นหนึ่งบรรทัดของแบบฟอร์ม ถ้าข้อความยาวเกิน Word จะตัดขึ้นบรรทัดใหม่และดันเอกสารเป็นสามหน้า
เครื่องมือวัดความกว้างด้วยฟอนต์ TH SarabunPSK แล้วบอกเป็นช่อง ๆ ว่า “เหลือ / บีบ / เกิน”
ถ้าเกินเล็กน้อยจะ **บีบระยะตัวอักษร (condensed)** เฉพาะช่องนั้นไม่เกิน `maxCondense`
(หน่วย 1/20 pt; 15 = 0.75 pt) ถ้ายังไม่พอจะเตือนเป็นสีแดง

จึงควรเขียนให้กระชับตามสำนวนศาล: `… กับพวกรวม ๑๙ คน`, ฐานะคำเดียว (`โจทก์` `จำเลยที่ ๑` `ผู้ร้อง`
`ผู้คัดค้าน`) — แต่ **ห้ามย่อชื่อคู่ความ** ให้ผิดจากคำฟ้อง ถ้ายาวจริงให้บอกผู้ใช้

### ๔.๔ ทนายความ

* ทะเบียนทนายเก็บในเบราว์เซอร์ของผู้ใช้ — ถ้าผู้ใช้มีอยู่แล้ว ส่งแค่ `lawyers: ["KT"]` ใน client
  และ **ไม่ต้องส่ง** อาร์เรย์ `lawyers` ระดับบนสุด ทนายที่ส่งมาจะเติมเฉพาะช่องที่ยังว่าง ไม่ทับของเดิม
* `idNo` ๑๓ หลัก ระบบตรวจเลขตรวจสอบ (หลักที่ ๑๓) และเตือนถ้าไม่ผ่าน
* `licenseNo` แบบ `เลขที่/ปี พ.ศ. เต็ม` เช่น `1234/2567`
* `phone` = โทรศัพท์ส่วนตัวของทนาย (บรรทัดที่อยู่ปัจจุบัน) · โทรศัพท์บรรทัดสำนักงานเป็นค่าคงที่ของสำนักงาน (`firm.officePhone`)

## ๕. กติกาสำหรับ AI

1. **ห้ามประดิษฐ์ค่า** — ชื่อ เลขคดี เลขบัตร เลขใบอนุญาต วันที่ ต้องมาจากเอกสารดิบเท่านั้น ไม่มีให้เว้นว่าง
2. **เลขไทย** ไม่ต้องแปลงเอง พิมพ์เลขอารบิกได้ (อีเมลคงอารบิก)
3. **หนึ่ง client = ลูกความหนึ่งราย** — หลายจำเลยที่สำนักงานรับว่าความให้แยกเป็นหลาย client
4. **ห้ามกรอกช่องคำสั่ง/ผู้พิพากษา** และห้ามเติมลายมือชื่อ
5. **บอกสิ่งที่ขาด** ทุกช่องที่เว้นว่าง ให้เขียนบอกผู้ใช้แยกจากไฟล์ว่าขาดอะไรและต้องหาจากไหน

## ๖. ไฟล์รุ่นแรก

ไฟล์ `.poa.json` รุ่นแรก (`"format": "juratools-attorney-appointment", "v": 1`) ยังเปิดได้:
`appts` → `clients`, `side: "defendant"` → แบบ JDA, ทนายในไฟล์แปลงเข้าทะเบียน (ที่อยู่ในไฟล์เก่าไม่ใช้แล้ว)
ส่วน `auth` ถูกเพิกเฉย เพราะข้อความเรื่องอำนาจใช้ตามไฟล์ต้นฉบับเสมอ
